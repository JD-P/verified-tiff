# Upstream fixture provenance

The initial seven TIFF files in this directory were copied unchanged from the `test/images`
directory of the libtiff 4.7.1 release, available from
https://download.osgeo.org/libtiff/tiff-4.7.1.tar.gz . The archive SHA-256 is pinned
in `toolchain-lock.json`; the upstream license is preserved as `LICENSE.md`.
The upstream image README describes the grayscale/RGB fixtures as 157 by 151
images named by photometric interpretation, channel count, and bit depth.

`manifest.json` records source and pixel hashes. For the lossless fixtures,
expected pixels were generated by the independently built libtiff 4.7.1 oracle.
The JPEG hash distinction is explained below. The test also compares directly to that oracle when installed.

`miniswhite-1c-1b.tiff` exercises uncompressed 1-bit WhiteIsZero with a 157-pixel
width, including byte padding at every row. Its source is copied unchanged;
the expected hash is over the oracle's expanded grayscale bytes.

Three more files prefixed `packbits-` were encoded by the pinned libtiff 4.7.1
`tiffcp -c packbits` tool from those original bilevel, grayscale, and RGB
images. Their precise source filenames and transformation arguments are in
`manifest.json`. They retain the upstream source-image license. Their expected
pixel hashes are the same independently generated hashes as the uncompressed
originals. This tests files produced by an independent encoder in addition to
the Python fixture writer.

Three `lzw-` files likewise use the pinned `tiffcp -c lzw:1` encoder, with
Predictor 1. Their transform arguments, input hashes, and unchanged expected
pixel hashes are recorded in the same manifest.

Three alpha fixtures derive from upstream `minisblack-2c-8b-alpha.tiff`, a
64x64 associated-alpha grayscale image. It is first decompressed without
changing planar layout, then interleaved and encoded as none/PackBits/LZW.
The intermediate step avoids random scanline access to compressed separate
planes. Both commands and the original source hash are recorded in the manifest.
Expected hashes come from native samples decoded by libtiff, normalized with
the independent rational-arithmetic reference in `tests/fixtures.py`.

Those additions brought the corpus to sixteen upstream-derived input fixtures, not a claim that the Rust implementation
passes the entire libtiff C API suite. The two cyclic main-directory fixtures
are decoded at page zero and tested for bounded behavior on large requests.
This reader follows at most the requested, bounded number of main-directory
links; it does not claim global acyclicity. SubIFDs are not followed.

The directory/endian/page behaviors exercised in `tests/integration.py` adapt
the relevant themes of upstream directory tests, including
`test/test_directory.c`. Writer APIs, codecs, recursive SubIFDs, allocation
callbacks, and C ABI tests are outside this first reader profile.

The test-only oracle supplies an exact-sized raw buffer through
`TIFFReadBufferSetup` for uncompressed FillOrder-2 tiles. In libtiff 4.7.1,
`_TIFFReadEncodedTileAndAllocBuffer` compares raw buffer capacity with tile
size, but the bit-reversal path can allocate capacity rounded to 1024 bytes.
That combination rejects valid smaller tiles. The supplied buffer avoids that
allocation mismatch without modifying TIFF bytes or libtiff source; libtiff
still performs all tag interpretation, bit reversal, and pixel conversion.

Six further unchanged originals cover palettes (1/4/8-bit), planar grayscale
alpha, and 16-bit grayscale/RGB. After Deflate the manifest contained 23 fixtures: 14
unchanged originals and 9 transcodes. The six new files use the independent
native-sample oracle, preserving 16-bit precision and planar alpha.

The unmodified libtiff 4.7.1 image `deflate-last-strip-extra-data.tiff` is
also included. Its last stream expands to a complete 16-row strip although
only four rows belong to the image. Both full stream validation and pixel
comparison are regression-tested. Provenance and hashes are in manifest.json.

Four unchanged JPEG/OJPEG originals are now included: quad-tile.jpg.tiff,
ojpeg_chewey_subsamp21_multi_strip.tiff,
ojpeg_zackthecat_subsamp22_single_strip.tiff, and
ojpeg_single_strip_no_rowsperstrip.tiff. The total is 27 fixtures: 18 unchanged
originals and 9 transcodes. For these lossy files, reference_pixel_sha256 is
the independent native-component oracle hash; pixel_sha256 records this
reader's deterministic fixed-point result. Live comparisons require equal
lengths and maximum channel error <=3, with matching nearest chroma. The
reference hash and bounded difference, rather than equality of the two hashes,
are the compatibility check. All source images retain the upstream license.

The unchanged `webp_lossless_rgba_alpha_fully_opaque.tif` is now included,
bringing the adopted set to 28 fixtures: 19 originals and 9 transcodes.
Its 20x20 RGBA output is compared exactly with the libtiff native oracle,
which now links pinned test-only libwebp 1.6.0. The stored pixel hash also
matches standalone libwebp RGBA decoding. The VP8L alpha-used hint is zero;
TIFF's fourth output channel is retained with all values 255. Source and pixel
hashes are recorded in the manifest, with the existing upstream license.

The unchanged `lzw-single-strip.tiff` brings the adopted set to 29 fixtures:
20 originals and 9 transcodes. Its 7,795×3,122 WhiteIsZero scan contains exact
packed storage but only five bits of its final 10-bit LZW EOI. The specified
sub-byte ending exception accepts it without filling or dropping pixels.
All 24,335,990 Gray8 bytes match both a test-only Python string-dictionary
decoder and libtiff. Its source/pixel hashes are in the manifest and the
original license is retained. The test-only RGBA oracle's allocation limit
was raised to 128 MiB to accommodate this image; decoder limits are unchanged.

The unchanged `quad-lzw-compat.tiff` brings the adopted set to 30 fixtures:
21 originals and 9 transcodes. Its 512×384 RGB image uses 77 old-style LSB LZW
strips with late width changes and continued references after dictionary
saturation. The 589,824 output bytes match both the independent Python string
dictionary and libtiff native oracle exactly. Source and pixel hashes are in
manifest.json; the original upstream license is retained.

The unchanged `logluv-3c-16b.tiff` brings the adopted set to 31 fixtures:
22 originals and 9 transcodes. Its 1x1 SGILog32 sample is decoded as native
LogLuv16 components `(0,6913,15544)`, stored as six little-endian bytes. The
expected hash comes from an independent rational conversion of packed word
`0x000056c2` and is checked against libtiff's SGILOGDATAFMT_16BIT output. This
is native HDR component output, not an RGB rendering. The file retains the
upstream license; source and output hashes are recorded in manifest.json.
